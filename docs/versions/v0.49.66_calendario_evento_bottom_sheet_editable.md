# v0.49.66 — Bottom sheet editable de evento en Calendario Día

## Objetivo

Convertir el bottom sheet «Editar evento» en una ficha realmente editable con todos los campos principales y acciones guardar/eliminar.

## Problema visual/funcional detectado

El sheet anterior mostraba filas de solo lectura (Fecha, Hora, Notas) sin campos editables reales. No permitía validar el flujo completo de edición ni incluía aviso ni eliminar de forma usable.

## Solución aplicada

**Bottom sheet editable** (`event_detail_sheet.dart`):

- Cabecera: título + Cancelar + vista previa (icono, título, hora, lugar)
- Campos editables: Título, Lugar, Fecha (picker), Hora (picker), Aviso (dropdown), Observaciones (multilínea)
- Botón principal: **Guardar cambios**
- Abajo del todo, separado: **Eliminar evento** (destructivo) con confirmación «¿Eliminar este evento?»

**Opciones de aviso:** Sin aviso, 5/10/15/30 min, 1 h, 1 día antes.

**Persistencia local (mock):** `CalendarDayView` mantiene `_localEventOverrides` y `_localDeletedEventIds` para aplicar cambios sin backend.

**Backend conectado:** guardar/eliminar delega en `Repositories.calendar` cuando el evento admite mutación servidor.

## Campos editables añadidos

| Campo | Control |
|-------|---------|
| Título | TextFormField |
| Lugar | TextFormField |
| Fecha | DatePicker |
| Hora | TimePicker |
| Aviso | Dropdown |
| Observaciones | TextFormField multilínea |

## Comportamiento de guardar

- **Mock:** devuelve `EventDetailSheetResult.saved` → vista Día actualiza estado local y refresca tarjeta expandida.
- **Backend:** PATCH vía repositorio + snackbar de confirmación.

## Comportamiento de eliminar

- Confirmación modal con Cancelar / Eliminar.
- **Mock:** devuelve `EventDetailSheetResult.deleted` → evento desaparece de la vista Día.
- **Backend:** DELETE vía repositorio existente.

## Archivos modificados

- `event_detail_sheet.dart` — reescritura completa del sheet editable
- `calendar_day_view.dart` — estado local mock + callback de edición
- `calendar_event_format.dart` — opciones de aviso para edición

## Conservado

Tarjeta expandida/colapsada, timeline, separadores libres, Semana/Mes, Home.

Ficha de edición premium, oscura y funcional para validar UX antes de backend real.

## Limitaciones

- **Mock temporal:** cambios en eventos mock solo persisten en la sesión de vista Día (no backend).
- El aviso en eventos backend no se envía al PATCH hasta que el contrato API lo soporte.
- Semana/Mes abren el mismo sheet pero no aplican overrides locales de vista Día.
